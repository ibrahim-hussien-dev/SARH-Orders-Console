The filter screenshot alone does **not** prove a race condition is prevented.
The browser test forwards requests to the real API, holds earlier responses,
renders the latest selection, releases the old responses and compares displayed
order ids again. Separate hook tests deliberately use a transport that ignores
AbortController, and prove stale success/error/loading cannot win, including the
exact 300 ms debounce boundary. An additional browser test releases a stale 503.

Network diagnostics include expected aborts from React StrictMode cleanup,
rapid filter changes and intentionally failed create responses. These are part
of the test, not unexplained production failures. The browser tests assert no
uncaught JavaScript errors or unexpected non-resource console errors.

The live duplicate script leaves two proof orders per run. It proves the
single-process live HTTP result, not a separate multi-process write race.
The SQLite immediate transaction and unique key are the implementation guarantee.
